# pyre 2: the workstream ledger

The second version of pyre is built on the branch `p2`, created from the release tag
`v1.13.1`. The name begins with a letter so that it can never be confused with a release
tag. Every effort that breaks first-version behavior is a workstream: it has a number, a
design document, and a sequence of phases. Each phase is developed on a branch named
`p2.<workstream>.<phase>`, created from `p2` and merged back into `p2` with a merge commit
whose subject names the phase. The dotted form is required: git cannot hold a branch named
`p2` beside branches named `p2/...`. Phases within a workstream are sequential; phases of
independent workstreams may proceed side by side. `p2` picks up fixes from main by merging
main into it and is never rebased. Main receives `p2` once, when the second version is
complete. Milestones on `p2` that downstream projects want to try are tagged as
pre-releases, `v2.0.0a1` and so on, since only tags can be pinned.

A new workstream registers here, with the next free number, before its first branch is
created.

## Workstreams

### 0. Components and the configuration store

Design: [lifecycle.md](lifecycle.md), sections 4 through 7, sequencing in section 11.

| phase | branch | scope |
|---|---|---|
| P1 | `p2.0.1` | the two stores: split, weak instance entries, release, guarded settings, fall-through to class defaults, reporting of unclaimed settings |
| P2 | `p2.0.2` | the syntax: `name@family` in cfg, pfg, and yaml; the toml reader; removal of pml; the command line; the migration tool |
| P3 | `p2.0.3` | the lifecycle: one construction path, identity, naming and renaming, binding events, containers as facilities, revisions, session state, the finalization hook, the recipe over the instance store |
| P4 | `p2.0.4` | the executive: the two-phase boot, the `pyre` instance, the accessor, removal of the dashboard, the journal cycle |
| P5 | `p2.0.5` | the consumers: `pyre.flow` on the new services, then the flow editor, the merlin builder, and the qed pipeline as acceptance tests |

## Salvage from the earlier `p2` branch

The branch that carried this name from January 2021 was reviewed on 2026-09-24 before
being retired. Nothing on it merges; three things are carried over by hand:

- the test `tests/pyre.pkg/tracking/here.py`, which pins the stack depth of locators;
- the test `tests/pyre.pkg/algebraic/ordering_containers.py`, which documents that an
  overloaded `__eq__` makes membership tests lie for tuples and lists but not for sets and
  dictionaries;
- the renames in `pyre.algebraic`: `AbstractNode` to `Node`, `cyclic` to `isCyclic`, the
  classifiers `leaves` and `composites`, and the `isNonNegative` constraint, as a to-do for
  whichever workstream next touches that package.
